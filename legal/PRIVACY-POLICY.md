# Raindrop Privacy Policy

Effective: November 6, 2026 · Version: 2026-11-06

Publisher: RiANDRAFT · Contact: riandraft@gmail.com

## 1. Scope and overview

This policy describes the Raindrop browser extension. It stores settings/content in your browser and can connect directly to services you choose. The extension has no built-in developer analytics or advertising system and does not upload your Raindrop content to a developer-operated storage service.

Third-party photo, quote, search, image, widget and backup providers receive data when their features run; their policies apply. Separately hosted websites may have hosting-provider logging and their own notices. Browser/extension-store processing is controlled by those providers. Information you voluntarily send for support is described below.

## 2. Local and session storage

Local extension storage can contain settings/layouts, names, links, clock/time-zone choices, notes/tasks, custom widget text/code/URLs, uploaded images, API-key settings, connection details, cached photo/quote data, consent/onboarding records, sync comparison records and recovery snapshots kept before replacement. Recovery snapshots may retain older content.

The GitHub sync token is stored separately in unencrypted local extension storage, even when the API-key vault is encrypted. Google tokens are obtained through the browser identity facilities. Raw unlock keys and per-widget access flags are kept in browser-managed extension session storage as well as used in memory, supporting session reuse across extension tabs and reloads. They are not included in portable exports/sync files. Browser session storage is not only a single tab's JavaScript memory.

Exported JSON files are separate files in the destination you choose. Protect your browser profile, downloads, credentials and backups; browser storage does not guarantee protection on a compromised device.

## 3. Encryption, locks and recovery

When enabled, Notes and Todos share an AES-256-GCM data key and encrypted payload. The shared password and recovery phrase derive separate wrapping keys through PBKDF2-SHA256 with stored salts/iteration metadata. The API-key vault uses a password-derived encryption key. Shared Account Settings additionally wrap that key using the private-data key so the same recovery phrase can recover linked API protection. Without the relevant encryption, local data and included notes/tasks can be plaintext. Encrypting these vaults does not encrypt the entire settings file.

Unlocked content and keys can be used in memory/session. Notes and Todos can be locked separately as application access/privacy controls: the selected plaintext view is cleared and reopening it requires authentication. They are not independently keyed vaults; while one remains open, the shared key can decrypt the payload. Lock both clears that shared key/session and both plaintext views. Widget locks do not lock API keys. Auto-lock/tab/session behavior depends on settings and browser facilities.

For linked Account Settings, the recovery phrase resets the password for API keys, Notes and Todos while retaining the existing private-data key and recovery phrase. It does not retrieve the old password. An API vault that predates linking still needs its existing password to join shared recovery. Wrapped master recovery metadata can be included with encrypted API backups even when Notes/Todos content is excluded; this does not include private note or task contents. Master-setting changes retain encrypted pre-change recovery snapshots. The developer does not operate password/key escrow. Without an applicable credential, usable unlocked session or recoverable copy, encrypted content may be inaccessible.

## 4. Network requests and recipients

Enabled features can contact Unsplash's API and photo hosts for queries/topics/collections, authenticated photo requests and photo-use/download reporting; Quotable/ZenQuotes/API Ninjas for quotes, with categories where supported and your key where required; and your chosen search engine or URL destination when you submit a search/navigate.

Remote images, embedded sites and custom-code destinations receive the URLs, requests and interactions generated by those widgets. GitHub/Gist hosts receive backup requests and API authentication; raw backup content can be fetched when necessary. Google identity/Drive APIs handle authentication and the app's Drive App Data backup. Providers can receive technical information such as IP address, requested URLs and browser/request metadata under their own policies. Relevant credentials are sent to the issuing API over HTTPS when required.

After acceptance, enabled features may load or refresh automatically on new tabs, timers, unlock, restored configuration or automatic sync. A separate click is not required for every request. Raindrop gates normal network-backed dashboard features on acceptance of the current legal version. Explicit provider account actions and navigation you initiate have their own effects; this is not a promise to control browser/store traffic or activity outside the extension.

Opening Developer team checks a public team JSON file through the GitHub API. GitHub receives ordinary request metadata such as your IP address and request headers; Raindrop does not attach your settings, notes, API keys, GitHub token or account credentials. Successful public team responses are cached in local extension storage for 24 hours, outside synced settings and backups; Refresh team requests a new check. Cached or bundled information remains available if the request fails. Team data can change between extension releases, but it cannot execute code, alter permissions, change app behavior or replace these Terms or Privacy Policy.

## 5. JSON export and cloud backups

Export and cloud backup use the same portable settings format. It includes layout/display preferences, links, custom widget definitions/text/code/URLs and uploaded custom-widget images. These categories are not encrypted by the Notes/Todos or API-key vaults. Uploaded custom-widget pictures travel as data URLs; uploaded background image bytes are excluded by the current serializer.

Include notes and todos when syncing also governs JSON export. When excluded, their content and notes vault are omitted. When included and encrypted, their ciphertext is included even while unlocked; pending included encrypted edits are flushed before serialization. Without encryption, included notes/tasks are plaintext. A receiving device's explicit notes-sync opt-out is not silently enabled by a remote backup.

An existing encrypted API-key vault is included automatically in the current export/backup. There is no separate per-vault inclusion switch. Designated plaintext key settings and device connection tokens are excluded; arbitrary secrets pasted into widget text/code/URLs/images or other freeform content are not detected or redacted.

Drive backup uses the app's hidden App Data space. Newly created Gists are secret/unlisted (public:false), not encrypted merely by that visibility setting. An existing Gist can be public or otherwise have different access; verify your chosen Gist's visibility and protect its URL. Providers may retain histories or other copies. Exported files can be read by anyone who obtains them except for individual fields protected by encryption.

## 6. Google access and disconnection

Where configured and supported, Raindrop requests the Drive drive.appdata scope for the app's hidden settings backup, not broad access to your Drive documents. Its use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. That data is used for the user-facing backup function, not advertising, sale or unrelated profiling. The developer does not routinely receive or manually inspect your Drive backup through this integration; information you voluntarily send for support is handled as described below.

Disconnect attempts provider revocation and browser token-cache removal, disables the local connection, and reports failures. Network/provider/token errors may prevent confirmed revocation; review/revoke access through your Google account if needed. Disconnect does not delete the backup or exported copies. Google sign-in is not implemented in the current Firefox preview.

## 7. Custom content and permissions

Custom sites/images/code may communicate with third parties independently of sync. The editor requests trust confirmation for new/changed embed or HTML widgets. Restoring saved configurations can load/run saved widgets without repeating each trust prompt. Only restore configurations you trust.

Chromium HTML/script widgets use a separate sandbox without the extension's storage APIs. Embeds can run third-party scripts and use third-party storage subject to browser/sandbox rules. Optional host access can enable frame rules that remove selected framing/CSP response headers for embedded subframes. Firefox preview blocks arbitrary HTML/script execution. These controls do not guarantee third-party content is trustworthy.

The optional Tabs permission supports page-search focus: new-tab URL metadata is examined to decide whether to replace an empty/new-tab page with an explicit extension page. The implementation does not create a browsing-history log or upload those tab URLs. Permissions, provider consent and session access are local browser grants/states, not transferred by backup.

## 8. Cookies, developer collection and support

The extension has no built-in analytics, advertising or tracking-cookie system. Functional local/session storage is described above. Third-party content, identity flows and services may use cookies or other storage under their own policies and your browser settings.

If you contact RiANDRAFT at riandraft@gmail.com, we receive what you choose to send, such as your email address, message and attachments. We use that information to respond, troubleshoot and meet applicable security/legal obligations, and retain it as reasonably needed for those purposes. Do not send passwords, recovery phrases, access tokens or personal backups unless you intend to disclose their contents for support. Contact us about information you voluntarily supplied; this is separate from automatic extension data collection.

## 9. Retention and deletion

Reset layout resets layout/style records; it does not erase all content. Reset all clears Raindrop's local extension storage, including local recovery snapshots and the saved GitHub token, and explicitly removes the API/Notes/Todos unlock session keys/access flags. Close other Raindrop tabs before resetting: other open tabs, browser facilities or external copies can retain state. This is not a guarantee of forensic erasure.

Reset all does not delete exported/downloaded JSON files, delete cloud backups/provider histories, revoke all provider access or browser permissions, or erase data from other installations. Use provider account and browser permission controls separately. Full lock clears the relevant unlock session without deleting the encrypted local data.

Removing the extension normally removes its extension storage as managed by your browser. It does not delete exported files or provider-held copies. Manage downloads, app data, Gists and account access separately; provider retention policies may preserve versions/copies after disconnection or deletion requests.

## 10. Security and your choices

Raindrop uses browser isolation, input validation, content-security controls and optional encryption. No method guarantees security on a compromised device, against malicious user-supplied code or at third-party services. Protect credentials, phrases, profiles and backups.

You can inspect/change local settings and use export, inclusion, reset, lock and provider controls within the limits above. The developer does not operate a remote copy-management service for your extension data. Depending on applicable law, you may have rights concerning personal information the developer actually receives, including support messages. Contact riandraft@gmail.com with requests; verification and legal exceptions may apply.

If you believe a child supplied personal information to the developer, contact riandraft@gmail.com so it can be addressed in accordance with applicable law.

Updates are published with a version/effective date. The extension presents review/acceptance when its legal version changes. Your browser's local acceptance record is not imported as proof of acceptance from another device. Review revised policies and stop using/remove the extension if you do not agree.
